### Camera | #k: camera,photo,record
- Avg 9 steps; 49% TAP 27% SWIPE 7% HOME (highest HOME rate)
- Viewfinder auto-displays; Shutter centered at bottom, desc "Shutter"
- Mode switch: horizontal swipe or tap "Switch to Camera/Video"
- Photos → /sdcard/Pictures/; Videos → /sdcard/Movies/
- **AOSP Camera2 default = VIDEO mode**: cold-launch always starts in video recording mode, regardless of intent. The mode ribbon (Photo | Video | Portrait) sits between the viewfinder and Shutter button; locate the clickable container whose children include Photo/Video/Portrait labels, or observe elements with text/desc matching these mode names. Mode label text may NOT appear in the accessibility tree — do NOT rely on element text to determine current mode. To switch modes: swipe horizontally ON the ribbon or tap the mode words directly. **NEVER press the Shutter to probe the current mode** — the Shutter is mode-dependent (tap starts recording in video mode) and may trigger an unintended side effect that wastes 2+ turns to undo. Resolve ambiguity via non-destructive means: inspect the mode-ribbon element labels (the mode-switch button label names the TARGET mode, not the current one), or verify via filesystem — `shell(ls -lt /sdcard/DCIM/Camera/ /sdcard/Movies/)` shows what prior captures produced (.jpg=photo, .mp4=video).
- If the goal is a photo capture but camera shows a timer after pressing Shutter → IMMEDIATELY stop recording (press Shutter again) and switch to photo mode before any real capture. Photo outputs land in /sdcard/DCIM/Camera/ or /sdcard/Pictures/; video outputs in /sdcard/Movies/. Some emulator images may not persist captures to disk — verify via the camera's own thumbnail/gallery view rather than only file system.
- **Sharing**: AOSP Camera2 has NO inline share button after capture. To share a photo/video:
  ① After capture → tap the thumbnail circle (bottom-right of viewfinder, shows last captured image)
  ② In the photo viewer → look for Share icon (usually top bar, ⋮ menu, or share icon). Do NOT press back from the viewer — that discards the sharing opportunity.
  ③ If thumbnail is not visible → back() → home() → open Photos/Gallery app → find the file → tap → Share
  Do NOT keep trying to find a share button inside the camera viewfinder — it does not exist there.

### Calendar | #k: calendar,event,simple calendar
- Avg 7.5 steps; 50% TAP 30% SWIPE (scroll-heavy)
- Month view + FAB(+) bottom-right (desc="New Event" id="calendar_fab"); New event: FAB → fill Title → set date/time → ✓ save
- ⚠️ DO NOT swipe in month view — it switches pages/tabs, not dates. Use TAP on date numbers only.
- To create event: launch app → tap FAB (desc="New Event") → tap "Event" option → form opens → fill Title/Description → set date/time → Save (top-right).
- ⚠️ Month-view day cells (id="month_view_background") have NO date text in the a11y tree — you cannot identify which cell is which day by reading the tree. Do NOT try to tap a specific day from the month grid. Instead, create the event from the FAB form and use the form's DATE FIELD to set the exact date.
- Event form date field: shows a label like "August 14 (Fri)". Tap it → a date-picker dialog opens with day-number cells → tap the target day NUMBER → tap OK. For relative dates ("in two weeks", "tomorrow"): compute the target day with shell(date -d '+14 days' '+%d %m %Y') (or +1 days) BEFORE opening the picker, then tap exactly that day number in the picker.
- Event form time field: tap it → time picker (hour/minute number pad) → tap hour then minute → OK.
- Save = TopAppBar Save/✓ icon (top-right corner), NOT a "Save" text button
- **Navigate to a specific date (for viewing/deleting events on that date)**: the app opens on DAY view with the date title at top (id="top_value", e.g. "August 13 (Thu)"). Tap the title → a 3-wheel date picker opens: month wheel (e.g. Jul/Aug/Sep buttons), day wheel, year wheel — with OK (id="button1") / Cancel (id="button2"). The CURRENT wheel value is the id="numberpicker_input" Input element (editable!).
  RELIABLE way to set the date — do NOT repeatedly tap the small prev/next value buttons (the wheel moves but taps land on the same coordinate and are unreliable):
  1. Tap the target month on the month wheel once (e.g. text="Jul" button).
  2. Tap the DAY wheel's numberpicker_input (the Input showing the current day) → select-all (long-press CTRL+A, i.e. key 29) → type the target day number (replaces the selection) → press enter. NOTE: do NOT use DEL/backspace key events — they behave unreliably here; select-all + type is the reliable path.
  3. Tap OK. Observe: the day view title must show the target date (e.g. "July 17 (Fri)").
  Compute the target day/month first: shell(date -d 'YYYY-MM-DD' '+%d %b') or shell(date -d '+14 days' '+%d %b').
- On the day view, event cards ARE in the a11y tree: id="event_item_holder" (clickable container) with child text id="event_item_title" (the title) and id="event_item_time" (e.g. "14:00 - 15:00"). If the event is later in the day than the visible window, scroll the day_events list.
- Delete event (verified path): tap the event card (event_item_holder) → "Edit Task" page opens → tap the DELETE button directly (desc="Delete" id="delete", top-right of the edit page — no ⋮ menu needed) → confirm dialog "Are you sure you want to proceed with the deletion?" → tap Yes (id="button1").

### OsmAnd | #k: osmand
- First launch: SKIP DOWNLOAD; permissions → Allow. After launch WAIT and re-observe: the a11y tree starts near-empty (0-8 elements) and fills in over seconds — resample before acting.
- ⚠️ BUTTONS ARE TAPPED, NOT TYPED: the words Search / Clear / INCREASE SEARCH RADIUS / Add / Marker / Save / Done name UI BUTTONS. NEVER type them into any text field. Only the PLACE NAME (e.g. "Times Square") is ever typed.
- Every tap: observe FIRST, then tap_element with the index from THAT fresh observe (never reuse an old index).
- Search: tap the Search button (desc="Search") → if the input keeps old text (the query PERSISTS across app restarts), tap the Clear icon (desc="Clear") → type ONLY the place name → key(enter).
- ⚠️ INCREASE SEARCH RADIUS: the button's label is a click=False Text inside a clickable row — tap the label's coordinates. Match the EXACT text "INCREASE SEARCH RADIUS" (the description "Change the search or increase its radius." also contains the word "increase" and is NOT the button). The maximum radius is 500 km — when the button disappears and the text becomes "Nothing found", STOP increasing.
- Two-stage search for far targets (VERIFIED, works at any distance): when the target is not found ("Nothing found" / "Could not find anything") → tap SHOW ON MAP (geocodes and centers the map) → tap Search again → Clear → type the place name → key(enter) → the result row now appears → tap it. Use this instead of burning many steps on the radius button for targets farther than ~500 km.
- Result rows are click=False Text elements (id="title") inside clickable parents — tap the text's coordinates.
- Tap a result row → a context card opens at the bottom (id="context_menu_line1"). Card buttons: Add (favorite) / Marker / Share / Actions.

- TRACK goal: card → Actions → Plan a route → the planner opens with points: 1 → tap the planner's Search icon (top-left) → search the next place → tap its result row → a card opens. ⚠️ While the card is open, its NAVIGATION button (bottom-right) COVERS the planner's bottom Add button — tapping Add's coordinates then starts navigation instead (a step trap). - ⚠️ Map overlay is opaque in the a11y tree, and the search-result tree is unstable (may briefly show only ~4 elements) — wait and re-observe before concluding "no results".

### Settings | #k: settings,wifi,bluetooth,brightness,airplane,flight
- Avg 7.5 steps; 48% TAP 27% SWIPE (most scroll-heavy category)
- Choose the path by goal shape:
  - **Bare system-toggle goal that names NO app** (e.g. "turn on wifi", "turn bluetooth off", "set brightness to X"): shell toggles are allowed, but ALWAYS check the current state first with a read-only query (`settings get ...`); if already at the target state, complete directly.
  - **Goal names the Settings app or any app UI** (e.g. "Open the Settings app...", "use the Settings UI..."): the change MUST be made through the Settings UI (launch → observe → tap/type → observe confirmation). Shell is QUERY-ONLY here (`settings get`/`dumpsys`) — use it to verify state, never to make the change.
- UI search: top bar type → key(enter)
- System toggle shell commands (read current state first; if already at target → complete directly):
  - Bluetooth: settings get global bluetooth_on | svc bluetooth enable/disable
  - WiFi: settings get global wifi_on | svc wifi enable/disable
  - Airplane mode: settings get global airplane_mode_on | settings put global airplane_mode_on 0/1
  - Brightness: settings get system screen_brightness | max = settings put system screen_brightness 255, min = settings put system screen_brightness 1 (NOT 0 — 0 turns the backlight OFF and is not the "minimum brightness" value; the valid min is 1)
- Direct settings page launch: am start -a android.settings.BLUETOOTH_SETTINGS / WIFI_SETTINGS / BATTERY_SETTINGS
- ⚠️ Settings search results often return developer options sub-items misleadingly — prefer am start to go directly to the target page
