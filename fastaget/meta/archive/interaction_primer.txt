## Android / iOS 通用交互约定

以下是移动端应用的**通用交互范式**——不是针对某个 App，
而是告诉你在特定界面类型下，有哪些手势/操作可以尝试。

### 通用手势探索策略（找不到目标元素时）

按优先级逐一尝试：
1. **屏幕外**：垂直滑动 scroll/swipe（列表页面常见）
2. **其他 tab/页面**：检查底部导航栏、顶部 tab 标签，尝试切换
3. **手势触发**：横滑、长按、下拉刷新（见下方界面类型）
4. **非 accessibility 节点**：取景器、游戏画面、播放器等 SurfaceView，用 ocr 兜底

**核心原则**：每次手势后 observe 确认；同一手势重复 ≤2 次即换策略；observe ≤5 个元素大概率是取景器/播放器模式，不是设备故障。

### 界面类型分类与交互约定

#### 1. 相机 / 取景器类（Camera、录屏、扫码）
- 特征：全屏取景器（SurfaceView），元素 ≤10 个
- 模式切换：横滑取景器 或 点模式标签（如 "Video"/"Photo"）
- 拍摄按钮：底部居中，desc 通常 "Shutter"
- 录制时 UI 树变空是正常现象
- 停止录制：再点同一位置
- 验证：shell(`find /sdcard -name "*.mp4"`) 或 content query
- ⚠️ 不要 ocr/run_script 找"缺失"元素——元素少是正常的

#### 2. 列表 / 可滚动界面（设置项、文件、联系人、短信）
- 找元素：scroll_to_find 优于手动 swipe
- 列表项操作：长按弹出上下文菜单
- 侧滑显示操作按钮（删除、归档）
- 长按第一项进入多选模式，顶栏出现批量操作

#### 3. Tab / 标签切换（浏览器、设置子页）
- 切换：tap_element 点 tab 文本，或内容区域横滑翻页
- 确认：observe 内容区域变化
- 离线 tab 的元素不在 UI 树中（ViewPager 特性）

#### 4. 底部导航栏（社交、购物主页）
- 切换：tap_element 点目标导航项
- 确认：observe 页面内容变化

#### 5. 侧边栏 / 抽屉菜单
- 打开：左边缘右滑 或 点左上角汉堡图标
- 关闭：点外侧区域 或 按 back
- 抽屉内元素只在打开时可见

#### 6. 弹窗 / 对话框 / 权限请求
- 权限弹窗："While using the app" / "Only this time" / "Don't allow"
- 引导页：连续点 NEXT/DONE/SKIP 直到主界面
- back 通常可关闭弹窗

#### 7. 文本输入 / 表单
- 流程：tap_element 聚焦 → type 输入 → key(enter) 提交
- 键盘遮挡：滑动页面或 back 收起键盘
- 搜索：type + key(enter) 后 wait(2) + observe 等结果加载
- 表单提交按钮通常在底部，需先滚到底

#### 8. 媒体播放器
- 播放区域 SurfaceView 不可见，控制栏在底部
- 控件自动隐藏——点播放区域重新显示
- 进度条通常不在 accessibility 树中

#### 9. 文件管理 / 文档
- 进入文件夹：tap 文件夹名；返回：back
- 选择文件：长按弹出操作菜单
- 新建：右下角 "+" FAB → 选文件/文件夹
- ⚠️ 红线：不能 shell echo/mkdir 冒充文件操作

#### 10. 设置 / 开关
- 开关：tap_element 点开关行切换，observe 确认
- 子菜单：tap_element 进入，back 返回
- 当前值显示为文字，不一定可点

#### 11. 网格 / 宫格（相册、应用抽屉）
- 查看详情：tap 缩略图
- 全屏浏览：左右横滑切换前/后
- 多选：长按第一张
- 退出全屏：× / back / 下滑

#### 12. 浏览器 / WebView
- 页面加载：操作后 wait(2-3) + observe
- 返回：back 回退上一页
- 网页元素 accessibility 标注可能不完整

### 操作纪律

**手势容错**：
- 横滑切换：从中间滑到另一侧（x1=720, x2=360），duration 300-500ms
- 竖滑滚动：从下半屏滑到上半屏（y1=1200, y2=600），duration 300ms
- 点错按钮：back 返回，不要 launch 重来

**UI 树变化 ≠ 故障**：
- 取景器/播放器模式元素少 → 正常
- 录制中 UI 树变空 → 正常
- 页面跳转中短暂为空 → wait(1) 后 observe

**禁止**：
- 不要 ocr/run_script 找取景器里"应该有"的元素
- 不要因元素少就 back/launch 重来——先分析界面类型
- 不要连续盲操作——每步必须 observe 确认
- 不要在手势后未观察效果就按 back——手势的效果可能是你需要的（如呼出隐
  藏菜单），盲目 back 会前功尽弃，导致无效循环
- 不要 shell 直写文件冒充 app 操作
